# Security scans (OWASP ZAP + Trivy)

Phase 13 contract §4 and acceptance §5: ZAP baseline + API scan of the running stack, Trivy scans of the repository
(dependencies, secrets), the built images and the configuration (Dockerfiles, Compose, Terraform). Acceptance: **no
unaccepted HIGH/CRITICAL findings**; every accepted one is listed with a reason (`.zap/rules.tsv`, `.trivyignore`).
The authorization matrix, IDOR, JWT tampering, header spoofing and rate-limit tests live in `tests/api-tests`
(tag `security`).

All reports go to `tests/security/reports/` (git-ignored).

| Script | Tool / image | What | Reports |
|---|---|---|---|
| `zap-baseline.sh` | `zaproxy/zap-stable:2.17.0` `zap-baseline.py` | passive scan + spider (+ AJAX spider for the SPA) of the **frontend** and the **gateway** | `zap-baseline-{frontend,gateway}.{html,json,md}` |
| `zap-api.sh` | `zap-api-scan.py` | **active** scan of the gateway's main routes as a signed-in customer, from an OpenAPI document generated by `zap/gen_openapi.py` (the services publish no OpenAPI) | `zap-api.{html,json,md}`, `gateway-openapi.json` |
| `trivy-fs.sh` | `aquasec/trivy:0.76.2` `trivy fs` | Maven (`pom.xml`) and npm (`package-lock.json`) dependencies, secrets in the repository | `trivy-fs.{json,txt}` |
| `trivy-images.sh` | `trivy image` | every local `grocery/*:dev` image: OS packages and the jars / node modules inside | `trivy-image-<name>.{json,txt}`, `trivy-images-summary.txt` |
| `trivy-config.sh` | `trivy config` | Dockerfiles, Terraform (built-in checks) and Docker Compose (`trivy-checks/compose-*.rego`, this repo's checks: infrastructure ports on all interfaces, default credentials, Docker socket/privileged, unpinned images, no memory limit) | `trivy-config.{json,txt}` |

## Run (Docker only)

From the repository root, with the stack up for the ZAP scans:

```bash
bash tests/security/zap-baseline.sh        # ≈ 8 min (two targets, spider + AJAX spider 3 min each)
bash tests/security/zap-api.sh             # ≈ 15 min (active scan capped at 12 min: the access token lives 15)
bash tests/security/trivy-fs.sh            # ≈ 1 min (first run downloads the vulnerability DB)
bash tests/security/trivy-images.sh        # ≈ 10 min for all images (first run downloads the Java DB)
bash tests/security/trivy-config.sh        # < 1 min
```

Exit codes: 0 = nothing unaccepted at HIGH/CRITICAL (Trivy) / no FAIL rule fired (ZAP); 1 = fail the pipeline.
Environment: `DOCKER` (docker command or a throttling wrapper), `ZAP_NETWORK`/`GATEWAY_URL`/`FRONTEND_URL`,
`ZAP_MINS`, `ZAP_AJAX`, `ZAP_SCAN_MINS`, `IMAGES`, `TRIVY_M2` (Maven repository volume, default `grocery-m2`).

Notes:
- The ZAP container joins `grocery_default`. Vite's dev server only answers allowed Host names, so the frontend is
  scanned by its container IP (`getent hosts frontend`); for a built frontend set `FRONTEND_URL`.
- `trivy fs` resolves Maven poms from the local Maven repository with `--offline-scan`: Maven Central answers a burst of
  pom downloads with 429 and blocks the IP for 30 minutes. Versions managed only by a BOM the cache lacks are not
  resolved — the image scan (the real jars) is the authoritative dependency scan.
- On Linux CI make `tests/security/reports` writable for the ZAP user (uid 1000): `chmod 777 tests/security/reports`.

## Accepting a finding

- **ZAP:** add `<rule id>\tIGNORE\t(<name>)` to `.zap/rules.tsv` with a comment line above: reason, who, date.
  `WARN` keeps it in the report without failing; `FAIL` makes the script exit 1.
- **Trivy:** add the id to `.trivyignore` with `exp:YYYY-MM-DD` (it comes back after that date) and a comment above:
  reason, where, the fix to watch for.
